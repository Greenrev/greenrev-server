Critical: anyone can take over the platform
Anyone can register as an admin through the normal sign-up. authController.ts:148 accepts role: "admin" from the request. After verifying their email, they have full admin access.
The admin sign-up is protected only by the code "GREENREV", written into the source code. authController.ts:87
Google sign-in also hands out admin. ?role=admin is accepted when the account is created. authController.ts:488, :596
The upload endpoint reads files before checking login. An anonymous visitor can send 10 × 50 MB files per request into server memory, so a few requests can crash the server. It also accepts any file type from any logged-in user. uploadRoutes.ts:17
Next.js has a critical-severity advisory in the installed version range (npm audit).
High
Server

CORS accepts every origin with credentials, and /auth/me returns the access token and CSRF token in its response. If cookies are ever set to SameSite=None, any website could read them. app.ts:45, authController.ts:276
Customers can see admins' internal support notes. GET /support/me returns every message, including ones marked internal. supportController.ts:27
Admin approve/reject of a KYC request doesn't change the user's verified status, so rejecting someone leaves them verified. adminController.ts:81
Admin permissions aren't enforced on the server. requirePermission is never used; permissions only hide sidebar items, so every admin can call every admin endpoint.
Two-admin approval for suspensions can be skipped: PATCH /admin/users/:id/status suspends directly. Role changes and deletions aren't written to the audit log either.
MFA does nothing. Users can enable it, but login never asks for the code. The secret is stored in plain text and returned by GET /profile. profileController.ts:10
Email PINs are guessable. They use Math.random(), are printed to server logs, last 24 hours, and have no per-account attempt limit. "Resend" adds new valid PINs without cancelling old ones. authController.ts:114, :124
Product search is open to regex injection and denial of service: name, make and color go straight into $regex, unescaped (productController.ts around lines 121–145). /products also has no pagination.
The receipt upload sends the receipt to Cloudinary before checking ownership, and accepts any string, including a remote URL that Cloudinary will fetch. acquisitionController.ts:379
A vehicle can be "sold" many times. Acquisition requests never check or reduce stock, and a customer can send unlimited duplicate requests for the same item.
Dependencies: high-severity advisories in axios, engine.io, form-data, follow-redirects and body-parser (npm audit fix resolves them).
Web

Web real-time notifications never connect. The socket sends only cookies, and the server looks for a cookie named accessToken when the real one is access_token. socket.ts:29, SocketContext.tsx:42
The AI chat costs money and is unprotected: /api/chat has no login, rate limit or message-size cap, so anyone can run up the OpenRouter bill. route.ts
The access token is copied to localStorage, which undoes the HttpOnly cookie: any XSS can steal it. apiClient.ts:17
Business KYC sends fake data: cacDocumentUrl: "url", businessAddress: "addr", bankAccountNumber: "123". There are no real upload fields. verification/page.tsx:52
Mobile

Users are effectively logged out after 15 minutes. There's no token refresh: mobile keeps only the 15-minute access token and drops the refresh-token cookie, so calls start failing and the next launch signs the user out.
Android release builds are signed with the debug key. build.gradle.kts:32
Notifications don't work on Android 13+: there's no POST_NOTIFICATIONS permission or runtime request. There's also no push service, so nothing arrives while the app is closed.

What you need to do

Admin sign-up is switched off until you set ADMIN_ACTIVATION_CODE on the server. Without it, /admin/register shows "Admin registration is disabled". Generate a long random value (openssl rand -base64 32), set it, and share it with new admins privately. The old "GREENREV" no longer works.
Look for admin accounts nobody expected. Run this against the production database:

db.users.find({ role: "admin" }, { email: 1, name: 1, createdAt: 1, status: 1 }).sort({ createdAt: -1 })
Any account you don't recognise could have come from these holes. Suspend or demote it, and use "revoke sessions" to log it out.
Deploy both projects: the server changes and the web's new package.json and package-lock.json.
